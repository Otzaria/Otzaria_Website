# עריכת עמודי ספרים אופליין

התכונה חלה רק על `/library/books/[path]/[pageNumber]`. אין מטמון של דפי הספרייה, מסכי ניהול, חשבונות או תשובות API. כלי עריכת הקבצים הישן אינו חלק מהתכונה.

## שימוש

1. התחברו, פתחו עמוד והכינו אותו דרך כפתור ההורדה בכותרת העורך: **אפשר עריכה אופליין לעמוד זה**. מומלץ לתפוס את העמוד תחילה כדי לצמצם עבודה מקבילה.
2. ההכנה מאמתת שהטקסט הנוכחי נשמר בשרת, מורידה את מעטפת העורך, קובצי הקוד והגופנים הנחוצים ואת צילום העמוד, ורק לאחר הצלחת כל השלבים מפרסמת עותק זמין. שמרו את כתובת העמוד בסימניות.
3. אפשר לערוך את הטקסט, לפצל ולאחד טורים ולפתוח מחדש את אותו עמוד בלי חיבור. בכל שינוי נשמרת מיד תמונת מצב מקומית, כולל שני הטורים ושמותיהם. פעולות התלויות בשרת, לרבות תפיסה, שחרור וסיום, דורשות חיבור. כלי אופציונלי שלא הורד מראש ותמונות חיצוניות המוטמעות בטקסט עשויים לדרוש חיבור.
4. כשהרשת חוזרת, השינויים מכל העמודים שהוכנו בחשבון מסתנכרנים כאשר עמוד עריכה כלשהו פתוח. יש גם סנכרון בחזרה ללשונית וכפתור סנכרון ידני. אין הבטחת סנכרון כשהדפדפן סגור. שגיאות רשת/שרת זמניות מנסות שוב בהשהיה גדלה עד דקה; שגיאות הרשאה והתנגשויות דורשות טיפול.
5. בחלון האופליין אפשר לראות עמודים שהוכנו, לעבור ביניהם, לייצא גיבוי JSON ולשחזר אותו לאותו חשבון ואותו עמוד. אחרי מחיקת נתוני הדפדפן יש להכין שוב את העמוד לפני יבוא גיבוי.

## הגנה על העבודה

- **שמירה במכשיר אינה שמירה בשרת.** יש חיווי נפרד לטיוטה שממתינה לסנכרון; סיום ושחרור דורשים אישור שמירה מהשרת.
- כל בקשת סנכרון קשורה לחשבון המקורי ולגרסת התוכן שממנה התחילה העריכה. השרת מאמת התחברות, בעלות בעמוד ונראות הספר מחדש. זהות מקומית מאפשרת קריאת העותק המקומי בלבד ואינה מעניקה הרשאת שרת.
- הגרסה היא SHA-256 של ערכי הטקסט, הטורים, סימוני המילים ומזהי הצילום/OCR. ההשוואה והעדכון מותנים אטומית גם בערכים המקוריים ובבעלות. גם עדכונים מלקוחות ישנים או עבודות OCR נלכדים בלי תלות במונה גרסאות חדש.
- התנגשות אינה נפתרת באמצעות דריסה אוטומטית. הטיוטה נשארת במכשיר; אפשר להשוות מול השרת ולבחור גרסה במפורש. בחירה מקומית עדיין כפופה לבדיקה אטומית חדשה. בחירה בשרת מורידה גיבוי לפני החלפת המקומית.
- הבקשה שבדרך נשמרת בנפרד מהטיוטה האחרונה. ניתוק אחרי כתיבה מוצלחת, הקלדה בזמן בקשה וסגירת הדפדפן אינם מוחקים את מזהה הניסיון הנדרש לשליחה חוזרת בטוחה.
- Web Locks מונעים עריכת אותו עותק בשתי לשוניות, מסדרים סנכרונים במקביל ונועלים גם הכנה והסרה של עותקים. קיצורי מקלדת בלשונית חסומה אינם רשאים לכתוב ליומן. לשונית שנייה מציגה הודעה ומבקשת לסגור את הראשונה ולרענן.
- רענון מהשרת של עותק ללא טיוטה מותר רק ללשונית שמחזיקה בנעילת העריכה. פרסום התוכן והצילום מסודר עם הסנכרון ובודק שהעותק לא השתנה מאז תחילת הבקשה; תשובה ישנה אינה מחזירה עותק שכבר סונכרן לגרסה קודמת. צילום שהוחלף מורד לפני עדכון הרשומה, וכשל בהורדה או באחסון משאיר את העותק הקודם שלם.
- כשל אחסון אינו מוצג כהצלחה. הטקסט האחרון נשאר בזיכרון העורך, מוצגת הודעה להורדת גיבוי ונחסמת יציאה שקטה מהדפדפן.

## אחסון, פרטיות ותאימות

נדרשים HTTPS (או localhost), Service Worker, CacheStorage, Web Locks ו-localStorage. אם אחד המנגנונים חסר, אי אפשר להפעיל את התכונה. אימות דפדפן נעשה ב-Chrome; אין כאן הבטחה שכל הגדרות הפרטיות או הדפדפנים מאפשרים אחסון קבוע.

הטקסט נשמר ביומן localStorage סינכרוני; הצילום ונכסי העורך נשמרים ב-CacheStorage. אין שמירת סיסמה, JWT או cookie בתוכן העותק. עם זאת, העותקים אינם מוצפנים ונגישים למי שמשתמש באותו דפדפן, גם אחרי יציאה מהחשבון. הנתונים מופרדים לפי חשבון, ספר ועמוד, ואינם מועלים בשם חשבון אחר.

הדפדפן רשאי לסרב לבקשת persistent storage או לפנות נתוני אתר. בגלישה פרטית, בניקוי נתוני אתר ובמכשיר עם מעט מקום אין הבטחת שרידות. טקסטים גדולים או תמונות מוטמעות עשויים למלא את מכסת האחסון. יש לייצא גיבוי של עבודה חשובה. אין אפשרות להסרה רגילה של עותק עם טיוטה שלא סונכרנה.

ה-Service Worker רשום רק תחת `/library/books/`. הוא מספק מעטפת מוכנה רק כשבקשת ניווט לעמוד עריכה נכשלת ברשת. 401/403, הפניה להתחברות או חסימת שבת מהשרת אינם מוחלפים בעותק מטמון. קובצי Next בעלי שם ממוספר נשמרים גם אחרי דפלוי כדי שטעינה אופליין תמשיך לעבוד. אין מחיקת מטמונים או טיוטות אוטומטית בזמן עדכון worker.

## אימות ותחזוקה

בדיקות `src/lib/offlineBooks`, בדיקות ראוט `/api/page-content` ו-`page.offline.test.jsx` מכסות שחזור טורים, אחסון מלא, הפרדת חשבונות, שמירה בזמן בקשה, תשובה שאבדה, עדכונים מקבילים, הרשאות וגבולות ה-Service Worker. יש לבדוק גם בניית production ובדפדפן אמיתי: הכנה, ניתוק, רענון, סגירת לשונית/פתיחה מחדש, הקלדה, חיבור מחדש והתנגשות יזומה.

יש לשמר תאימות ליומן `v1` ולמטמונים קיימים בשדרוגים. בהסרת התכונה יש להשאיר endpoint ל-worker חלופי שמפסיק מטמון ומאפשר גיבוי/סנכרון; אין למחוק טיוטות במסגרת rollback.

תהליך `Book editor offline QA` ב-GitHub Actions מריץ את בדיקות האופליין וההרשאות מול MongoDB אמיתי, ודוחה הרצה שדילגה על בדיקות. הוא בונה production ומריץ Chromium, כולל התאוששות אוטומטית מ-503, חסימת לשונית שנייה ורענון צילום בלי להסתמך על מטמון ה-HTTP. אפשר לקבוע תיקיית ראיות לסקריפט הדפדפן באמצעות `OTZARIA_BOOK_OFFLINE_ARTIFACTS`; ה-CI שומר את הלוגים, הצילומים וראש הקומיט שנבדק כ-artifact.

לבדיקת דפדפן ניתנת להרצה חוזרת: התקינו Playwright מקומית (אין שינוי חובה בתלויות האפליקציה), ואז הריצו `node scripts/test-book-offline.cjs`. הסקריפט יוצר MongoDB זמני, בונה production, מפעיל שרת בפורט פנוי, בודק אופליין/סנכרון/התנגשויות/פקיעת התחברות ומנקה את נתוני הבדיקה. אפשר להעביר `OTZARIA_PLAYWRIGHT_MODULE` לנתיב מודול Playwright שכבר מותקן ו-`OTZARIA_CHROME_EXECUTABLE` ל-Chrome מקומי. הלוגים והצילומים נשמרים בתיקייה זמנית שהסקריפט מדפיס. בדומה ל-CI הקיים, הבנייה דורשת את ראש תגית v1 של חבילת הוולידטור.
