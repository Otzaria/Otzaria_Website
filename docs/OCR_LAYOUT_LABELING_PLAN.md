## הרקע והצורך

שכבת התבנית של פרויקט ה-OCR (ראה `OCR-AI/docs/LAYOUT_LAYER.md`) מנקה
אוטומטית כותרות רצות, מספרי-עמודים וזרמי-טקסט ב-57 מהדורות (3,341 עמודים),
ומדגלת בדיוק את מה שהיא לא הצליחה להכריע:

| דגל | משמעות | היקף נוכחי |
|---|---|---|
| `pagenum_conflict` | מספר-העמוד שנקרא סותר את הרצף הצפוי | ~741 עמודים |
| `stream_link_uncertain` | חלוקת הזרמים בעמוד לא שודכה בביטחון | ~504 עמודים |
| `no_header` | לא נמצאה כותרת רצה בעמוד בספר-עם-כותרות | ~120 עמודים |
| 7 מהדורות "קשות" | שערים / סריקות עקומות / תבניות מרובות | ~350 עמודים |

**העיקרון: המכונה כבר עשתה את העבודה — המתנדב רק מכריע.** לכל עמוד מדוגל
יש prefill מלא (תיבות, ערך צפוי, חלוקת זרמים). לכן זו איננה משימת "תיוג
עמוד מאפס" אלא **מיקרו-שאלות ממוקדות**: ברוב המקרים לחיצת "נכון" אחת,
או הקלדת ערך קצר. התשובות חוזרות לפרויקט ה-OCR כקובץ הכרעות-אדם, ומשמשות
גם את אימון מודל-החיתוך det-v2 (אזורי-ignore מאומתים).

## סוגי המשימות (מהקל אל המורכב)

### 1. `pagenum` — "מה מספר העמוד?" (הנפוץ והקל ביותר)
- מוצג: חיתוך מוגדל של רצועת מספר-העמוד + הערך הצפוי מהרצף (למשל "יט").
- המתנדב: ✔ "נכון" / הקלדת הערך הנכון (גימטריה או ספרות) / "אין מספר עמוד".
- שניות בודדות למשימה; ולידציה חיה של גימטריה (מודול `gematria` קיים בפרויקט OCR — ייכתב מקבילו הקטן ב-JS).

### 2. `header` — "האם זו כותרת רצה?"
- מוצג: הרצועה העליונה של העמוד עם התיבה המזוהה מודגשת + נוסח הכותרת הספרית.
- המתנדב: ✔ "נכון" / גרירת תיבה מתוקנת / "אין כותרת בעמוד".

### 3. `streams` — "חלוקת הזרמים"
- מוצג: העמוד המלא עם פסי-רוחב צבעוניים לפי חלוקת המכונה, ומקרא זרמי-הספר
  (פנים / הערות / ...) מתוך התבנית.
- המתנדב: גרירת קווי-הגבול האופקיים, הוספה/הסרה של גבול, ובחירת זהות
  לכל רצועה מהמקרא. ✔ "נכון" כשהחלוקה טובה.

### 4. `zones-full` — עמוד מלא (7 המהדורות הקשות)
- שילוב 1–3 במסך אחד: כותרת + מספר + זרמים. אותו canvas, כל השכבות.
- זה המסלול היחיד שמצריך עבודה של ממש; מוגש אחרון (שלב 3).

עמוד אחד = מסך אחד: כל השאלות של אותו עמוד יחד, עם כפתור "הכול נכון"
כשה-prefill מדויק. קיצורי מקלדת: Enter=אישור, N=הבא.

## ארכיטקטורה — לפי הדפוסים הקיימים

### מודל: `OcrLayoutPage` (חדש, נפרד — כמו `OcrLine`/`OcrTrainingPage`)
```js
{
  batch: String,            // מזהה אצוות-ייבוא (למשל "hard7-2026-07")
  edition: String,          // ed057 — מזהה המהדורה בפרויקט ה-OCR
  pageStem: String,         // p0012 — שם העמוד בפרויקט ה-OCR
  imagePath: String,        // /uploads/ocr-layout/<batch>/<edition>/<stem>.jpg
  imageWidth, imageHeight: Number,

  tasks: [{                 // המיקרו-שאלות של העמוד
    kind: 'pagenum' | 'header' | 'streams' | 'zones-full',
    prefill: Mixed,         // תיבות/ערך-צפוי/רצועות — כפי שיוצאו מה-resolved
    answer: Mixed,          // הכרעת המתנדב (null עד שנענתה)
    confirmed: Boolean,     // true = "המכונה צדקה" בלחיצה אחת
  }],

  status: 'available' | 'submitted' | 'approved',   // כמו OcrLine
  leasedUntil: Date,        // החכרה רכה — כמו OcrLine
  answeredBy / answeredByName / answeredAt / approvedAt,
}
```
- שמירה אטומית first-wins בעדכון pipeline יחיד — אותו מנגנון של `OcrLine`
  (mongoose 9: `updatePipeline`).
- אינדקסים: `{status, leasedUntil}` להגשת משימות; `{batch, edition, pageStem}` ייחודי.

### צד ה-OCR (סקריפט חדש בפרויקט OCR-AI)
`scripts/export_labeling_batch.py` — קורא `resolved.jsonl` + תבנית + תמונות
עמודים, בורר עמודים מדוגלים (או מהדורה שלמה ל-hard7), ומפיק ZIP:
- `tasks.jsonl` — שורה לעמוד: מזהים, מידות, המשימות עם ה-prefill
  (תיבות בפיקסלים, הערך הצפוי בגימטריה, רצועות הזרמים + מקרא זרמי-הספר).
- `images/<edition>/<stem>.jpg` — תמונות העמודים (המקור אינו באתר: מהדורות
  הקורפוס אינן "ספרים" באתר, ולכן התמונות מצורפות לאצווה).

### ייבוא (Admin)
`/library/admin/ocr-layout` → העלאת ה-ZIP → פריקת התמונות אל
`/uploads/ocr-layout/<batch>/…` ויצירת מסמכי `OcrLayoutPage`. ייבוא חוזר של
אותה אצווה = upsert לפי המפתח הייחודי (לא כפילויות). מוצג פירוט: כמה עמודים,
כמה מכל סוג משימה.

### דף המתנדב: `/library/ocr-layout`
- הקצאה: עמוד אחד בכל פעם (בשונה מ-10 שורות בתמלול — כאן היחידה היא עמוד),
  בהחכרה רכה בעדכון מותנה — בדיוק כמו `linePool`.
- רק משתמשים מאומתים (`requireVerifiedSession`).
- UI: תמונה + שכבת SVG/canvas לתיבות ולרצועות (שימוש חוזר במודול `geometry`
  של ocr-training); טופס השאלות בצד. RTL מלא.
- תמונות מוגשות רק דרך `GET /api/ocr-layout/[id]/image` (+`?crop=…` לרצועות
  מוגדלות) — לא כנכס סטטי; הוספה ל-proxy המוגן כמו ocr-lines.

### ניהול: `/library/admin/ocr-layout`
- למנהל גלובלי בלבד (כמו שאר אזורי ה-OCR — ‏commit ‎47e8491).
- רשימה עם סינון לפי אצווה/מהדורה/סטטוס/סוג-משימה; תצוגת התשובה על העמוד;
  אישור / החזרה לעריכה / מחיקה; עריכת תשובה בידי המנהל לפני אישור
  (כמו ב-ocr-lines — ‏commit ‎f1b47a0).
- ייצוא: JSONL זורם של המאושרות — `<edition>.human.jsonl`, שורה לעמוד:
  `{page, pagenum:{value|null}, header:{box|null}, streams:[{y0,y1,book_stream}], by, at}`.
  ‏cursor + backpressure כמו בייצוא ocr-lines.

### צריכת התוצר בפרויקט ה-OCR (מחוץ לאתר, שלב המשך)
`apply_template.py --human <ed>.human.jsonl` — הכרעות-אדם גוברות על המכונה:
מוחקות דגלים, מתקנות רצף מספור (עוגני-אדם משפרים את התאמת-הרצף לכל הספר),
ומזינות אזורי-ignore ל-det-v2.

## עקרונות (ירושה משני המישורים הקיימים)
- **prefill תמיד** — המתנדב מכריע, לא יוצר מאפס (ספק = שאלה, לא ניחוש).
- תפיסה/החכרה אטומית; שמירה first-wins; ולידציה כפולה (לקוח+שרת).
- תמונות רק דרך API מאומת; ניהול למנהל גלובלי בלבד.
- ייצוא זורם בפורמט שפרויקט ה-OCR צורך ישירות, כולל `contributors.tsv`.

## מצב תפעולי (עודכן 14/07/2026)

### מצב-קישור (linked) — ברירת המחדל בפועל
האצוות אינן מעלות תמונות: כל רשומה נושאת `ref` (bookId+pageNumber) ומצביעה
לתמונת-הספר הקיימת (`/uploads/books/<slug>/page.N.jpg`). ה-prefill מיוצא
במרחב הסריקה המקורית (הופכי-deskew בצד OCR-AI), ולכן מתלבש עליה ישירות.
מסמכי `OcrLayoutPage` מקושרים נושאים `book/bookSlug/pageNumber`.
הערה: התמונות קיימות רק בשרת הייצור — ב-localhost ה-viewer יציג רקע ריק.

### סקריפטי תפעול (ב-`scripts/`, מחוץ לגיט בכוונה — כמו יתר סקריפטי seed)
- `seed-ocr-layout.js --file <batch.jsonl> [--dry-run] [--purge-batches a,b
  --purge-editions e1,e2]` — ייבוא-בכמות ישירות ל-Mongo (עוקף אימות-HTTP).
  הטיהור מוחק רק עמודים available לא-מוחכרים; עמודים שנענו לעולם לא.
- `seed-ocr-layout-imagemap.js <needed.json> <book_map.json> <out.tsv>` —
  מפת imagePath להורדת תמונות-הקורפוס בצד OCR-AI.
- אם הסקריפטים חסרים (checkout חדש): המבנה שלהם מתועד בפרויקט OCR-AI —
  `scripts/run_layout_round.sh` (ה-driver שקורא להם) + `docs/LAYOUT_LAYER.md`.
