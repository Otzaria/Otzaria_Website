# חנות אוצריא — תוספים עם שירות מקומי

**גרסה:** 2

מסמך זה קובע את ההתנהגות המבוקשת. המימוש כבוי כברירת מחדל (`SERVICE_PLUGINS_ENABLED`) עד מעבר בדיקות הקבלה ב־`STAGING.he.md`. הוראות ההפצה למפתחי תוספים נמצאות ב־`DEVELOPERS.he.md`; התקנת רכיבי הבדיקה ב־`DEPLOYMENT.he.md`; המתווך ב־`workers/service-plugin-broker/`.

## 1. גבולות המערכת

החנות תקבל תוסף רגיל יחד עם מתקין של שירות חיצוני, לפי בחירה יזומה של מנהל. אין רשימת מפתחים מורשים ואין הרשאת מנהל לעקוף ממצא אבטחה. בחירה למסלול השירות אינה מחייבת הצגת התוסף גם ברשימת ה״נבחרים״ השיווקית בדף הבית.

היעד הוא סריקת נוזקות מוכרות וחסימת סיכוני אבטחה ברורים, בתקציב מצומצם. אין בנייה מחדש, בדיקות תפקוד של השירות או התחייבות לביצועים. מקור ציבורי נגיש לסקירה נדרש; אין דרישה לרישיון מסוג מסוים. התאמה לקובץ Release מוכיחה זהות קבצים בלבד. הקשר בין הבינארי למקור נקבע באישור בנייה של GitHub Actions (סעיף 5.2): הוא מוכיח שהקובץ נבנה מה־commit ומה־workflow שהוגשו, אך לא שתהליך הבנייה עצמו נקי. לכן קובצי ה־workflow וסקריפטי הבנייה הם חלק מחובה של הסקירה.

המתקין **כולל בתוכו** `.otzplugin`, מחלץ אותו מקומית ומפעיל את מסלול `install-local`. זו אינה הורדת קוד. התקנת שירות ברקע, הרשאות מערכת מוצדקות ורכיבים הכלולים במתקין אינן עילה לדחייה. הורדת קוד חדש או עדכונים העוקפים את החנות אסורה; הורדת נתונים מותרת רק אם טעינתם אינה משמשת להרצת קוד. הסרת התוסף אינה מסירה את השירות. לא יפותח מנגנון הסרה או סימון מסוכנות מרחוק.

## 2. זרימת המשתמשים

**מפתח:** בטופס הקיים יסמן ״דורש שירות חיצוני״. פרטי התוסף וקובץ התוסף יעברו את בדיקת ה־SDK הקיימת, ללא AI. הוא יועבר לדף הגשת השירות ויצרף מקור מוצמד ל־commit, קובץ תוסף עצמאי, מתקינים לכל מערכת ופרטי זיהוי/הסרה. במימוש הראשוני זהו טופס המשך: בוחרים בו שוב את קובץ התוסף שאליו מתייחסים המתקינים. סיום ההעלאה מקפיא את ההגשה ומעביר אותה ל״ממתין לבחירת מנהל״; לא מתחילה סקירה בתשלום.

**מנהל:** יראה שם, גרסאות, מצב ברור ו״בחר בתוסף והתחל בדיקה״. הלחיצה היא אישור הפרסום המותנה: אם כל הבדיקות יעברו, אותה הגשה תפורסם אוטומטית. אין לחיצה נוספת ואין צורך לקרוא קוד. תקלה תפעולית מוצגת בנפרד עם הנחיה להעביר לאחראי השרת. דחייה מפיקה דוח למפתח ואינה מצריכה החלטת אבטחה של המנהל. בממשק המנהל יוסבר שההגנה העיקרית היא זהות הקבצים, אישור הבנייה וסורקי הנוזקות; סקירת המקור בידי AI חלקית מטבעה.

**מוריד:** בכרטיס ובדף התוסף יסומן ״דורש שירות חיצוני״. פתיחת אפשרויות ההורדה מפעילה זיהוי מקומי; אין סריקת פורטים של כל התוספים בעת טעינת קטלוג. שירות מזוהה בגרסה תואמת מציע רק תוסף קטן, להורדה או להתקנה באוצריא. בכל מצב לא ודאי נשארת בחירה בין המתקין לתוסף בלבד. זיהוי שירות לא תואם מודיע שנדרש עדכון. אין תשובה מהשירות פירושה ״לא הצלחנו לזהות״, לא ״לא מותקן״.

מערכת לא נתמכת תוצג באופן מעומעם, עם אפשרות לבחור מערכת אחרת ולהוריד למחשב אחר. ארכיטקטורה נבחרת ידנית כשיש כמה קבצים; אין להסתמך על User-Agent להכרעה בין x64 ל־ARM64. גרסת מערכת מינימלית מוצגת לפי הצהרת המפתח. זיהוי דפדפן עלול להיחסם או לדרוש הרשאה; אין לבטל הורדות ידניות בגלל כשל זיהוי [S3].

אזהרה קבועה: ״התוכנה החיצונית פועלת ברקע גם כשאוצריא סגורה. התחזוקה, האיכות וצריכת המשאבים תלויות במפתח. הסרת התוסף אינה מסירה את השירות. בדיקות החנות אינן מבטיחות היעדר תקלות או סיכוני אבטחה.״

## 3. נתונים וזהות הגרסה

| מקום | נתונים מחייבים |
|---|---|
| `Plugin` | `hasService` קבוע למסלול; `serviceState.pending`, `currentPluginReview`, `currentServiceReview`, `previousServiceReview`, מערכות נתמכות, חריגת מנהל, אסימון וזמן נעילת בדיקה |
| `ServicePluginReview` | בעלים ותוסף, סוג הגשה, גרסאות וטווח תאימות, מקורות ו־commits, קבצים/גדלים/תפקידים/SHA-256, אישורי בנייה מאומתים (מאגר, commit, נתיב workflow, סוג runner), פורט זיהוי לכל מערכת, מניפסט קפוא ו־digest, מצב, בחירת מנהל, זמן התחלה, ניסיונות ומכסה, קבלות שלבים, החלטה ודוח |
| `ServiceScanControl` | נעילה יחידה לכל הבודקים ותאריך חידוש מכסת Claude; מונע צריכת סקירות מקבילות באותו מנוי |
| אחסון האתר | `SERVICE_PLUGIN_STORAGE_DIR/<reviewId>/plugin` ו־`native0..native7`; מחוץ ל־`public`, שמות שרת בלבד, ללא החלפת קובץ קיים |
| אחסון הבודק | עותקי עבודה, מקור שנשמר, השוואת fingerprints, יומן שלבים ומזהה שיחת Claude מסוימת; ללא גישה של הדפדפן |

זהות ההגשה היא digest של מניפסט קנוני הכולל **את כל** ה־hashes, המקורות, פרטי התאימות וגרסת מדיניות הבדיקה. החלטה אינה קשורה רק ל״תוסף מספר X״. החלפת פרטים מחייבת ביטול ויצירת הגשה חדשה; תשובה ישנה לא יכולה לפרסם אותה. שדות מזהים ונתיבי קבצים אינם נלקחים מפלט המודל.

מגבלות התחלתיות שנבחרו למימוש וניתנות לשינוי בקוד המדיניות: תוסף 50 MiB; מתקין 256 MiB; עד שמונה מתקינים, אחד לכל צירוף מערכת/מעבד; עד ארבעה מקורות בהגשה; גרסאות `X.Y.Z`; דוח עד 64 KiB. שלוש הגשות פעילות למפתח נבדקות בשרת, ובכל תוסף יש נעילה אטומית להגשה פעילה אחת. קלט מקור מוגבל ל־24 MiB טקסט, 5,000 קובצי טקסט ו־2 MiB לקובץ; חריגה אינה אישור חלקי. פורט הזיהוי ייחודי לכל מערכת בין כל תוספי השירות שפורסמו או ממתינים; הגשה עם פורט תפוס נחסמת ביצירה, ובעלות על פורט עוברת רק עם התוסף.

## 4. מכונת מצבים ומגבלת הבדיקות

```text
draft → sealing → pending_admin → queued → running → approved / rejected
                               running → retry_wait → running
                               running → waiting_quota → running
                               running → needs_operator
כל מצב פעיל → cancelled; approved/rejected אינם נבדקים שוב אוטומטית
```

העלאה מותרת רק בטיוטה, פעם אחת לכל מפתח קובץ. חתימה סופית דורשת שכל הקבצים הגיעו ושה־SDK והמניפסט תואמים. הגשה ממתינה אינה מחליפה גרסה ציבורית קיימת. ביטול מפקיע את נעילת הפרסום לפני שינוי הסטטוס. בודק מחזיק הרשאה קצובה ל־120 שניות ומחדש אותה כל 25 שניות; אובדנה מפסיק את התהליך ומונע פרסום מאוחר. ביטול בזמן ריצה משאיר את הנעילה הגלובלית עד פקיעת ההרשאה, כדי ששתי בדיקות לא יחפפו. פקיעת הרשאה חמש פעמים באותה הגשה מעבירה אותה לטיפול תפעולי, בנפרד ממונה הניסיונות.

**21 יום:** נספרים מהתחלת בדיקת שירות חדשה, גם אם נדחתה או בוטלה. בקשת מנהל שלא התקדמה מעבר לתור כבר נחשבת להתחלת מחזור הבדיקה. העלאות ותיקונים לפני כן דורשים חריגה חד־פעמית עם סיבה; החריגה נצרכת בהתחלת הבדיקה ולא עוקפת שום בדיקה. ניסיונות חוזרים של אותה הגשה אינם מחזור חדש. עדכון תוסף בלבד אינו כפוף ל־21 יום, אך חייב בחירת מנהל וסקירת השינוי בהקשר השירות המאושר; אינו משנה את המתקינים, הפורטים או הוראות ההסרה.

תקלה זמנית, כולל עצירה בידי שומר התקיעה (סעיף 5.5): עד שני ניסיונות נוספים, אחרי דקה ואחרי חמש דקות. דחייה תקינה אינה ניסיון חוזר. שגיאת התחברות, חיוב, חריגת הקשר או סריקה לא מלאה עוברת לטיפול תפעולי. מכסת Claude מוצתה: השהיה משותפת לכל תור Claude עד מועד האיפוס שדווח בשדה פרוטוקול אמין ועוד דקה. ללא מועד אמין: שש שעות ועוד דקה; אחרי שתי המתנות לא ידועות נדרש מפעיל. המכסות של GitHub ו־VirusTotal מתוזמנות בנפרד ואינן מוצגות כבעיית Claude. לא מפעילים API בתשלום כגיבוי.

## 5. צינור הבדיקה

1. **קוד שרת/בודק קבוע:** אימות hashes וגדלים, סריקת ClamAV, אימות התאמה לקובץ Release, חילוץ סטטי של התוסף מתוך כל מתקין והשוואתו לתוסף העצמאי. אין להריץ מתקין כדי לחלץ אותו; פורמט שאינו ניתן לחילוץ נעצר — בהם מתקיני Inno Setup ו־WiX Burn, ש־7-Zip אינו פותח. ClamAV ו־7-Zip מופעלים עם ארגומנטים מוגבלים, לא פקודות מן המפתח. הם מפענחים קלט עוין, ולכן רצים כמשתמש מערכת נפרד, ללא רשת וללא גישה לסוד המתווך; בידוד זה הוא תנאי הפעלה.
2. **אישור בנייה (provenance):** לכל מתקין נדרש אישור `actions/attest-build-provenance` של GitHub, המאומת בבודק ב־`gh attestation verify <file> --repo <owner/repo>` מול ה־SHA-256 של הקובץ שנקלט. האישור חייב להצביע על אחד המאגרים שהוגשו ועל ה־commit שהוגש עבורו, ולהעיד על runner של GitHub (לא self-hosted). אישור חסר, לא תקין או שאינו תואם — דחייה, לא תקלה תפעולית. נתיב ה־workflow מתוך האישור מועבר לסקירה (שלב 5) כקובץ חובה [S6].
3. **VirusTotal, אופציונלי:** כבוי כברירת מחדל. הפעלה רק אחרי אישור תנאי השימוש ומפתח API מתאימים והסכמת המפתח לשיתוף הקובץ. חיפוש hash מדויק תחילה, ניצול דוח עדכני, העלאה/סריקה כשנדרש, שמירת analysis ID והמתנה מוגבלת. זיהוי malicious או suspicious אחד חוסם לפי מדיניות, ללא האשמת כוונה. חוסר תוצאה או מנוע שלא השלים אינם ״נקי״. רישיון ומכסה הם תנאי תפעולי, לא חלק משיקול הדעת של AI [S1].
4. **הכנת מקור וסינון קבוע:** משיכת מקור ציבורי לפי commit מלא; לא `git clone` עם hooks ולא התקנת dependencies. קריאת ארכיונים בגבולות קשיחים, דחיית נתיבים/קישורים/קלט לא תקין. כל קובץ מוצג למודל בשם מספרי בטקסט; `CLAUDE.md` וקובצי הגדרות מתוך המקור אינם הופכים להגדרות הבודק. נבנה INDEX והבדל מול המקור המאושר הקודם, כולל שינויים בקבצים בינאריים ותלויות. סינון דטרמיניסטי, ללא AI, מפיק רשימת ״קבצים לבדיקה״ עם השורות שזוהו: הורדה מהרשת, הרצת תהליכים, `eval`/טעינת קוד דינמית, PowerShell/shell, כתובות URL קשיחות, Registry, רישום שירותי מערכת והרשאות מוגבהות, האזנה לרשת שאינה loopback, טיפול ב־Host/Origin בנקודת הזיהוי, וכל קובצי ה־workflow, סקריפטי הבנייה וקובצי התלויות. הרשימה היא הכוונה לסקירה, לא החלטה: ממצא בה אינו דחייה אוטומטית, והיעדרו אינו אישור.
5. **Claude Code אחד:** רואה אינדקס, שינויים, רשימת ״קבצים לבדיקה״ והקשר מלא נגיש לקריאה. חייב לסקור את קובצי ה־workflow והבנייה שבאישור הבנייה ואת רשימת הסינון, ומעבר להם בוחר עומק מידתי. אין מגבלת צעדים או זמן לניסיון; הסקירה מסתיימת כשהמודל מחזיר החלטה, או בחריגת הקשר/מכסה (סעיף 4). **שומר תקיעה:** המתווך מודד התקדמות לפי אירועים בזרם הפלט המובנה של ה־CLI, ולא לפי זמן כולל. אם לא הגיע אירוע חדש במשך 10 דקות, המתווך עוצר את עץ התהליכים של ה־CLI ומדווח תקלה זמנית לפי סעיף 4. סקירה ארוכה שממשיכה להפיק אירועים לא תיעצר. אין Bash, עריכה, MCP, אינטרנט בכלי המודל או סוכנים נוספים. הוראות המדיניות בקובץ מהשרת, לא מהמאגר. תוכן קובצי המקור הוא נתון בלבד: ניסיון להורות לבודק בתוך הקוד הוא ממצא בדוח. אי אפשר לשלול לחלוטין השפעה של טקסט כזה על המודל, ולכן זו מגבלה מוצהרת של הסקירה. הבודק אינו נשלח לערוץ OpenClaw כללי בעל כלים רחבים. הוא משתמש באותה יכולת Claude Code דרך תהליך מתווך קבוע ומוגבל; חיבורו לפריסת OpenClaw בפועל הוא שלב תפעולי. אופן ההתחברות של Claude נקבע במפורש בהגדרת המתווך (מפתח API או מנוי) ואין לו ברירת מחדל. לפי עמוד התנאים של Claude Code, התחברות מנוי מיועדת לשימוש אישי רגיל, ושירות הפועל עבור אחרים צריך מפתח API; לפני הפעלה יש לוודא שהבחירה עומדת בתנאים [S2].

פלט תקין: `{"decision":1,"report":"סיכום בעברית פשוטה; היקף הסקירה, ממצאים ומגבלות"}`. ההחלטה והדוח מגיעים יחד. רק אירוע סיום מובנה של CLI יוצר החלטה; לא מחפשים את המילה ״מכסה״ בתוך טקסט שהמודל כתב. לכל שלב נשמרת קבלה עם digest. קבלה ודוח נשמרים לפני בקשת הפרסום, כך שניתוק בזמן השליחה אינו מצריך סקירה חדשה. אם עותק המקור הקודם חסר, עוברים לסקירה מלאה ולא מנחשים ש״אין שינויים״.

## 6. פרסום, חזרה לאחור וניקוי

אחרי `1` יש לוודא שכל הקבלות הנדרשות שייכות לאותה הגשה. כתיבת מצביעי הגרסה, מטא־דאטה והיסטוריה נעשית בעדכון מותנה יחיד של `Plugin`: תוסף לא מוסתר/מושהה, אותה הגשה פעילה, אותה גרסת בסיס והרשאת בדיקה בתוקף. אין העתקה דורסנית לקובץ חי. כשל בכתיבת סטטוס הסקירה אחרי עדכון המצביע מתאושש ל״פורסם״, בלי להריץ AI מחדש. כשל בשליחת מייל אינו מבטל פרסום ואינו מפעיל סקירה.

נשמרים מתקיני השירות הנוכחי והקודם בלבד, בנוסף לקבצים של הגשה פעילה. תוספים קטנים שכבר פורסמו ודוחות נשמרים כהיסטוריה. חזרה לאחור מחליפה את מצביע השירות ואת מצביע התוסף הכלול בו יחד; אינה צורכת סקירה ואינה מאפסת 21 יום. היא אינה משנה תוכנה שכבר הותקנה במחשבי המשתמשים. לא ממחזרים מספרי גרסה שכבר פורסמו, גם אחרי חזרה לאחור.

כל נתיבי ההורדה, כולל קישורים ישירים והיסטוריים, בודקים שוב אישור/השהיה וזהות הגרסה. מתקינים מעבר לקודמת אינם מוצעים. בחירת גרסה אוטומטית לפי גרסת אוצריא לא תבחר זוג שירות/תוסף היסטורי בלי זיהוי שירות. הורדה מפורשת של תוסף ישן נשארת עם אזהרת תאימות.

ניקוי שעתי: טיוטה לא גמורה לאחר 24 שעות תבוטל, והגשה שלא נבחרה בידי מנהל תוך 30 יום תבוטל; ביטול לפני התור מוחק את קבצי ההגשה מיד, וקבצי הגשות אחרות שבוטלו/נדחו יימחקו אחרי שבעה ימים; נעילת תוסף שמצביעה על הגשה שהסתיימה או חסרה משתחררת; מתקינים שאינם נוכחי/קודם יוסרו. דוחות והיסטוריית בדיקות אינם נמחקים. ניקוי הבודק משאיר את סביבת הגרסאות הפעילות והקודמת. גיבוי וניטור שטח פנוי נדרשים בשרת.

## 7. חוזה API ונקודות חיבור

הנתיבים החדשים תחת `/api/service-plugins`. בקשות מפתח/מנהל דורשות session מתאים; כל כתיבה מדפדפן דורשת Origin האתר. JSON מוגבל ל־200,000 בתים. קובץ מתקין נשלח ב־PUT גולמי בזרימה ולא נטען כ־multipart ענק בזיכרון.

| פעולה | נתיב ושיטה |
|---|---|
| פרטי הורדה ציבוריים | `GET /<pluginId>` |
| מידע אישי והגשות | `GET /<pluginId>/manage` |
| יצירת הגשה | `POST /<pluginId>/drafts` — מבנה הבקשה במדריך המפתח |
| העלאת קובץ | `PUT /<pluginId>/drafts/<reviewId>/assets/plugin` או `native0..native7` |
| הקפאה/ביטול | `POST /<pluginId>/drafts/<reviewId>/seal`; `DELETE /<pluginId>/drafts/<reviewId>` |
| הורדה מוצמדת | `GET /<pluginId>/download/<reviewId>/<fileKey>` |
| חזרה לאחור בידי הבעלים | `POST /<pluginId>/rollback` |
| רשימת מנהל | `GET /admin` |
| פעולת מנהל | `POST /admin/<pluginId>` עם `action=start/cancel/retry/emergency/rollback`, ובמידת הצורך `jobId` או `reason` |
| מתווך בלבד | `POST /worker/claim`, `maintenance`; פעולות `<reviewId>/heartbeat`, `checkpoint`, `failure`, `result`, וקבלת `asset/<key>` |
| ניקוי שעתי | `GET`/`POST /api/cron/service-plugins-cleanup` עם `CRON_SECRET` |

המתווך מזדהה בסוד שרת ייעודי; לכל משימה אסימון lease נוסף. הסוד אינו עובר ל־Claude או לכלי פירוק הארכיונים. חסימת הורדות אינה תלויה בכפתור אפור בצד לקוח. העריכה הישירה הקיימת נחסמת לתוספי שירות גם עבור מנהל.

**תוסף החנות בתוך אוצריא:** קודו לא שונה בחבילה זו. לצורך שילובו יש להשתמש ב־API הציבורי החדש ובאותו חוזה זיהוי, ולהציג בחירת מתקין/תוסף. עד שילוב זה, API העדכונים הוותיק מחזיר `requiresServiceCheck:true`, קישור לחנות ו־`hasUpdate:false` לתוספי שירות, כדי לא להתקין עדכון שאולי אינו תואם לשירות. אין בכך השלמה של ממשק תוסף החנות או כלי העדכון אופליין. מצב זה חוסם גם עדכוני תוסף בלבד מתוך אוצריא, ולכן תמיכה מודעת־שירות בתוסף החנות ובמעדכן האופליין היא תנאי להפעלה לציבור. המעדכן יכול להסתמך על `plugin_install_results.jsonl` שבשורש נתוני אוצריא, שרושם תוצאה לכל בקשת `install-local` לפי `path`.
