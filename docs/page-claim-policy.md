# מכסת עמודים בעריכת ספרים

מתנדב יכול להחזיק חמישה עמודים בטיפול בכל הספרים הציבוריים יחד. ספר אישי
(פרטי או בעל `ownerId`) ופעולות מנהל ספרייה פטורים. תפיסות ציבוריות שלא נערכו
חמישה ימים משתחררות; כל שמירת תוכן תקינה מעדכנת את זמן הפעילות.

## אטומיות ב-MongoDB standalone

לכל תפיסה מוגבלת נשמרים ב-`Page` השדות האופציונליים `quotaUserId` ו-`quotaSlot`
(מקום 0–4). האינדקס הייחודי `page_claim_quota_slot` חל רק על עמודים בטיפול.
הקצאת המקום ושינוי הסטטוס נעשים באותה כתיבה מותנית של העמוד. תפיסה וביטול סיום
משתמשים באותו מקצה; בקשה שנדחתה אינה משנה את העמוד ואין פעולת ביטול מאוחרת.
שינוי הסטטוס לסיום או לפנוי מפנה את המקום מיד, בלי עדכון מסמך משתמש נוסף.

אין דרישה ל-replica set. לפני הקצאה חדשה המימוש ממתין במפורש ליצירת האינדקס,
גם אם `autoIndex` כבוי. אם בניית האינדקס נכשלת, ההקצאה נכשלת ולא עוברת למסלול
לא מוגן. אין לשנות/למחוק את האינדקס בזמן שהאתר פעיל.

לפני הקצאה משחררים בפועל את תפיסות המשתמש שפג תוקפן בכל הספרים, ואז ממפים
תפיסות קיימות למקומות באמצעות עדכונים מותנים שאינם משנים `updatedAt`.
אין צורך במיגרציית נתונים ידנית. משתמש שכבר החזיק יותר מחמישה עמודים לפני
הפריסה רשאי להמשיך לערוך אותם, אך אינו יכול להוסיף עמוד עד שירד מתחת למכסה.

שמירת תוכן מוגנת גם ב-`status`, ב-`claimedBy` וב-`claimedAt` שנקראו. אם העמוד
שוחרר או נתפס מחדש בזמן הבקשה, השמירה הישנה נעצרת ב-409 במקום לדרוס את הכותב
החדש. שמירה בעמוד פנוי נשארת אפשרית ואינה משנה אותו אוטומטית לעמוד בטיפול.

## בדיקות

`Book claims QA` מריץ את בדיקות המדיניות, התפיסה, ביטול הסיום והשמירה מול
MongoDB standalone אמיתי. `REQUIRE_MONGODB_TESTS=1` הופך אי-זמינות של המסד
לכישלון בדיקה; בדיקות מדולגות אינן הוכחה לנכונות.

הרצה מקומית:

```sh
MONGOMS_VERSION=7.0.24 REQUIRE_MONGODB_TESTS=1 node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --test src/lib/pageClaimPolicy.test.mjs src/lib/bookPageClaims.int.test.mjs
MONGOMS_VERSION=7.0.24 REQUIRE_MONGODB_TESTS=1 node node_modules/vitest/vitest.mjs run src/app/api/book/uncomplete-page/route.test.js src/app/api/page-content/route.test.js src/app/api/page-content/claim-quota.test.js
```
