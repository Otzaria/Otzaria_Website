# הגהה וחלופות לפי ההקשר

הרחבה אופציונלית לחוזה העובד המקומי. הטקסט אינו מתוקן אוטומטית: ההצעות מוצגות בעורך ומוחלות רק בבחירת המתנדב.

## אפשרויות עבודה

`options.lm` נשאר התחום (`rabbinic`, `modern`, או `off` הישן), ו־`defaultScript` נשאר ללא שינוי.
נוספו שדות אופציונליים:

| שדה | ערך | משמעות |
| --- | --- | --- |
| `lmCheck` | `on` / `off` | בדיקת מודל השפה, בנפרד מהתחום. `modern` עם `lmCheck:off` נשאר ספר מודרני. |
| `alts` | `on` / `off` | `on` מבקש ספירות הקשר וחלופות. חישוב ראשון עשוי להוסיף 7–25 דקות. |
| `lexicons` | רשימת עד 16 שמות | חסר: ברירת המחדל במחשב; `[]`: אף מילון נוסף; רשימה: רק המילונים שנבחרו. |

שמות מילונים מוגבלים ל־60 תווים: אותיות עברית/אנגלית, ספרות, `_` ו־`-`. נתיבי קבצים אינם מתקבלים.
רשימת מילונים מנורמלת בסדר קבוע, ומפתחות ההרחבה משתתפים בטביעת הבקשה ובמפתח הבקשה בדפדפן.
עבודה ישנה ללא השדות שומרת את המעטפה ואת טביעת הבקשה הקודמות בדיוק; אין הזרקת ברירות מחדל לעבודות קיימות.

## דיווח יכולות

השירות שולח, באימות העובד הרגיל, `POST /api/worker/v1/capabilities`:

```json
{
  "schemaVersion": 1,
  "proofreading": {
    "version": 1,
    "lmCheck": true,
    "alternatives": true,
    "lexiconAvailable": true,
    "contextAvailable": true,
    "lexicons": [{"name": "modern", "version": 1}],
    "defaultLexicons": []
  }
}
```

עד 50 מילונים, גוף עד 16KiB. `defaultLexicons` אופציונלי וחייב להיות תת־קבוצה של הקטלוג.
האתר שומר רק את השדות המוכרים, קושר אותם לעובד המאומת וחותם את זמן הקבלה בעצמו.
דיווח ישן מ־15 דקות מוצג כ־`stale`. דיווח חסר אינו מאפשר בחירה באפשרויות החדשות, אך משאיר את הפעלת ה־OCR הישנה זמינה.
השרת בודק תמיכה וזמינות מילונים לפני יצירת עבודה חדשה. ניסיון חוזר/המשך עם אותו `requestId` והגדרות שמורות אינו תלוי בדיווח יכולות חדש.

בממשק המנהל התחום ומתג מודל השפה נפרדים כשיש תמיכה. החלופות כבויות כברירת מחדל, מופעלות בפעולה מפורשת, ומוצג זמן החישוב האפשרי.
בזמן `progress.phase=context` מוצג שחישוב ההקשר עדיין פעיל וניתן לביטול. הממשק שומר עבודות ישנות ללא הרחבות גם כאשר דיווח יכולות מגיע בזמן שהן פעילות.

## תוצאת ההגהה

לכל סימון יכול להופיע `alts:[{text,p,why}]` בשתי הרמות, `fix` ו־`check`.
לכל היותר שלוש חלופות, טקסט וסיבה עד 200 תווים, `p` סופי בטווח 0–1 (או חסר).
חלופה יכולה להכיל שתי מילים. כפילויות ומילה זהה למקור או ל־`sugg` אינן מוצגות.
`p` הוא **משקל יחסי בין החלופות**, ולא הסתברות שהחלופה נכונה. החלופות נשמרות בנפרד מ־`sugg`; הוספתן אינה משדרגת `check` ל־`fix`.
בעורך המילים החשודות שדה התצוגה הוא `contextAlternatives`. מסלולי הגהת השורות שומרים את `alts` בתוך הסימון.
סימונים אינם עוברים למילה ששונתה, והחלטת ״המילה תקינה״ נשמרת למופע שנבחר בלבד.

כשל בהעשרת ההקשר אחרי OCR אינו משליך את הטקסט. השירות מחזיר `metadata.proofreading` עם `requested:true`,
`status` שהוא `ready`, `unavailable`, `failed` או `skipped_salvage`, וסיבת כשל קבועה לפי החוזה.
האתר שומר ומציג את המצב גם כאשר metadata גדול קוצץ, ומציג בנפרד שהחלופות לא חושבו.
קודי אזהרה: `proofreading_alternatives_unavailable`, `proofreading_alternatives_failed`, `proofreading_dictionary_unavailable`.
אם מילון נוסף נעלם אחרי זיהוי שמור, המשך/הצלה יכולים לשמור את הטקסט בלי המילון החסר, עם `reason:dictionary_unavailable` ותווית מפורשת שהמילון לא שימש בהגהה. עבודה חדשה עם אותו מילון חסר נדחית לפני OCR.

## סדר פריסה

יש לפרוס קודם תמיכה באתר בקליטת שדות הרשות ובדיווח היכולות, ואז את השירות והפייפליין התואמים.
השירות הישן ממשיך לקבל מעטפות ישנות ללא הרחבות; הממשק פותח את האפשרויות החדשות רק אחרי דיווח השירות המעודכן.
יש לבדוק מקצה לקצה: יצירה, המשך, ביטול בזמן ההקשר, העברת `check` עם חלופה, פיצול לשתי מילים, ואישור מופע בודד של מילה חוזרת.
